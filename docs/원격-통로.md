# 고객 PC 원격 통로 — 개통·회수 절차

1판 2026-10-12. 근거: 한 고객 PC 개통 기록(1시간 20분 걸린 시행착오)과 고객 환경 접속 기준 초안.
비밀값(키·비밀번호·IP·tailnet 이름)은 이 문서와 저장소 어디에도 쓰지 않는다. 사례는 익명으로만 적는다.
개통할 때마다 [양식/원격통로-개통기록.md](양식/원격통로-개통기록.md) 를 복사해 채운다.

## 1. 개통 전 체크리스트

| # | 확인 | 이유 |
|---|---|---|
| 1 | **고객 명의 통로**: 고객이 Tailscale 기기 공유 링크를 열고, 언제든 끊을 수 있게 한다 | 통로의 주인이 고객이어야 회수·중단이 고객 손에 있다 |
| 2 | **로그인·결제·시스템 권한 승인은 고객 손으로** | 우리가 대신 눌러 주지 않는다 |
| 3 | **전용 로컬 계정**을 새로 만든다 (고객 본인 계정 사용 금지) | 아래 2절 |
| 4 | 전용 계정은 **일반 사용자**로 둔다. 관리자 권한은 작업 때만, 고객 승인 후 부여하고 끝나면 회수 | 최소 권한. 부여·회수 시각을 기록 |
| 5 | 개통기록 양식을 복사해 고객·기기·날짜부터 적는다 | 회수 때 무엇을 지울지 기록으로 안다 |

### 왜 고객 본인 계정을 쓰지 않나
- 고객 계정이 **비밀번호 없음**이면 윈도우 기본 정책이 그 계정의 네트워크 로그온을 막는다.
- 풀려면 `LimitBlankPasswordUse` 를 꺼야 하고, 그러면 SMB 파일공유까지 빈 암호로 열린다. **풀지 않는다.**
- 대신 전용 로컬 계정을 만든다. 회수 = 계정 삭제 한 번.

## 2. 키 규칙

| 규칙 | 내용 |
|---|---|
| 기기별 키 | 우리 맥 한 대당 키 하나. 키를 여러 기기에 복사하지 않는다 |
| 주석 | `ops-<고객>-<기기>-<날짜>` (예: `ops-acme-macbook-20261012`). 고객 PC의 공개키 줄에 이 주석이 붙는다. **고객 약칭은 영문·숫자만** 쓴다(한글 금지). 회수 때 `-Encoding ascii`로 파일을 다시 쓰면 비ASCII 글자가 `?`로 바뀌어, 고객의 다른 키 주석까지 망가질 수 있다 |
| 암호 | **모든 개인키에 암호 필수.** 무암호 키 금지. 무인 접속이 꼭 필요하면 별도 판단(담당자 승인) |
| 회수 | 주석으로 우리 키만 골라 지운다(고객의 다른 키는 보존). 3절 회수 체크 참고 |

## 3. 막혔을 때 — 순서

### 3-1. 잠금 정책을 끄지 않는다
`net accounts /lockoutthreshold:0` **금지**. 윈도우 11 은 기본으로 실패 10회에 계정을 잠그는데, 키·비밀번호 설정 중 반복 실패가 계정을 잠가 "한 번 성공한 뒤 다시 막힘"이 생긴다.
잠긴 동안은 키 로그인도 끊긴다(리허설 실측). 그래서 kit은 **전용 계정만 sshd 비밀번호 로그인을 끈다**(6절). tailnet 안에서 SSH로 틀린 암호를 넣어 잠그는 길은 막히지만, 화면·다른 경로의 실패로는 여전히 잠길 수 있으니 이 절차는 그대로 쓴다.

1. **먼저 잠김 여부 확인**
   ```powershell
   $u = [ADSI]"WinNT://$env:COMPUTERNAME/<전용계정>,user"
   $u.psbase.InvokeGet('IsAccountLocked')      # True 면 잠김
   ```
   서버 로그에 `0xC0000234`(STATUS_ACCOUNT_LOCKED_OUT)가 보여도 같은 상태다.
2. **해제만 한다**
   ```powershell
   $u.psbase.InvokeSet('IsAccountLocked',$false); $u.psbase.CommitChanges()
   ```
3. 잠긴 근본 원인(반복 실패)을 고친다. 아래 흔한 원인 참고.

### 3-2. 흔한 원인 (먼저 의심할 것)
| 증상 | 원인 | 조치 |
|---|---|---|
| 서버 로그 `Connection closed by authenticating user ... [preauth]` | 서버 거부가 아니라 **클라이언트가 끊은 것**. 개인키에 암호가 걸렸는데 `BatchMode=yes` 라 암호를 물을 수 없어 ssh 가 포기 | 맥에서 `UseKeychain yes`+`AddKeysToAgent yes` 또는 askpass 로 암호 공급. 이 반복 실패가 계정 잠금으로 이어진다 |
| 관리자 계정인데 키가 안 먹음 | 윈도우 sshd 는 Administrators 그룹 계정의 개인 `authorized_keys` 를 읽지 않고 `C:\ProgramData\ssh\administrators_authorized_keys` 만 읽는다 | 해당 파일에 등록 + 소유자 `Administrators` (`icacls <파일> /setowner "Administrators"`) + ACL 정리 + sshd 재시작 |
| `sshd.exe -d` 를 관리자 PowerShell 에서 띄웠더니 항상 `unable to generate user token ... not running as system` | 포그라운드 디버그는 SYSTEM 이 아니라 늘 이 오류로 끝난다 — 진짜 원인이 아님 | 서비스로 돌리고 파일 로깅(`SyslogFacility LOCAL0` / `LogLevel DEBUG3` → `C:\ProgramData\ssh\logs\sshd.log`) |
| `sshd_config` 에 `LogLevel` 을 추가했더니 오류 | 파일 끝에 붙이면 마지막 `Match` 블록 안으로 들어가 허용되지 않는 지시어가 된다 | **첫 `Match` 앞에** 끼워 넣는다. 단 새 `Match` 줄로 시작하는 블록은 앞 블록을 닫으므로 파일 끝에 붙여도 된다(kit의 전용 계정 블록이 이 방식) |

### 3-3. 원인이 아니었던 것 (여기서 시간 쓰지 않는다)
한 고객 PC 실측 기록 기준.

| 후보 | 판정 근거 |
|---|---|
| 방화벽 | SSH 인사말 수신 + KEX 완료 — 막는 거라면 거기까지 못 온다 |
| 백신(V3 등) | 위와 동일. 끄지 않고 해결됨 |
| 빈 비밀번호 정책 | 비밀번호를 가진 전용 계정도 똑같이 거부됐다 |
| 네트워크 로그온 거부 정책 | `SeDenyNetworkLogonRight` 에 Guest 만 있었다 |
| sshd 서비스 계정 | `LocalSystem` 확인 |

### 3-4. 고객 보안 설정을 낮춰야 할 때
- 고객 **승인**을 먼저 받는다. 승인 없이 낮추지 않는다(백신·방화벽·실행 정책 끄기 금지는 CLAUDE.md 그대로).
- 무엇을·누가 승인했는지·언제 원복했는지를 개통기록에 적는다. 원복 기록이 없으면 회수가 끝난 것이 아니다.

## 4. 회수 체크 (계약 종료·세션 종료 때)

개통기록 양식의 "회수" 칸을 채우면서 진행한다.
kit로 개통했다면 `uninstall.ps1 -SshUser <전용계정>`이 아래 칸 중 전용 계정 키 → 관리자 키 → 계정·프로필 세 가지를 이 순서로 한다(계정 삭제는 묻는다). 나머지 칸은 사람이 확인한다.

- [ ] 일반 계정 파일부터 정리: 전용 계정의 `.ssh\authorized_keys`에서 우리 키(주석 `ops-<고객>-`)를 지운다. 계정을 지우기 전에 해야 파일 경로가 남아 있다
- [ ] 관리자 권한을 줬었다면 회수하고 시각 기록
- [ ] `%ProgramData%\ssh\sshd_config` 끝의 우리 표식 블록(`# BEGIN ax-field-kit access-account` ~ `# END ax-field-kit access-account`, 전용 계정 비밀번호 SSH 끄기)을 지우고 `sshd -t` 확인. `uninstall.ps1`이 `-KeepSsh`여도 지운다(백업 `sshd_config.bak-axfieldkit-<시각>`). 고객의 다른 줄은 건드리지 않는다. 지우는 것은 `-SshUser` 계정의 블록뿐이다(표식에 계정 이름이 들어 있음). 한 PC에 전용 계정이 둘 이상이면 다른 계정의 블록은 남고, 그 계정의 비밀번호 SSH 끄기도 그대로다. `-SshUser`를 빼고 실행하면 블록을 하나도 지우지 않는다
- [ ] 관리자 키 파일에서 우리 키만 골라 지운다 (고객의 다른 키는 보존)
  ```powershell
  $A = Join-Path $env:ProgramData "ssh\administrators_authorized_keys"
  (Get-Content $A) | Where-Object { $_ -notmatch 'ops-<고객>-' } | Set-Content $A -Encoding ascii
  ```
  `-Encoding ascii`는 비ASCII를 `?`로 바꾼다. 파일에 고객의 한글 주석이 있는지 먼저 보고, 있으면 이 명령을 쓰지 말고 사람이 해당 줄만 직접 지운다.
- [ ] 프로필 먼저, 그다음 계정을 지운다 (`uninstall.ps1`과 같은 순서). 계정만 지우면 `C:\Users\<전용계정>`이 남는다. 프로필이 사용 중(접속·로그인 중)이거나 삭제에 실패하면 **계정을 지우지 않고 멈춘다** — 계정이 남아 있어야 SID로 프로필을 다시 찾을 수 있다
  ```powershell
  $sid = (Get-LocalUser <전용계정>).SID.Value
  Get-CimInstance Win32_UserProfile -Filter "SID='$sid'" | Remove-CimInstance   # 실패하면 여기서 멈춘다
  Remove-LocalUser -SID $sid
  ```
  접속을 끊은 뒤에도 Windows 가 재부팅 전까지 프로필을 잡고 있을 수 있다(리허설 실측). `uninstall.ps1`이 "프로필이 아직 로드돼 있습니다"로 멈추면 PC를 다시 시작한 뒤 `uninstall.ps1 -SshUser <전용계정>`을 다시 실행한다(키·방화벽 회수는 이미 끝남). 강제 언로드·프로세스 강제 종료는 하지 않는다.
- [ ] Tailscale **Sharing 취소** (고객이 공유 링크/기기 공유를 끊음, 또는 관리 콘솔 Machines → ⋯ → Sharing)
- [ ] 낮춘 보안 설정이 있었다면 원복 확인
- [ ] **고객에게 회수 완료를 확인받고** 확인 시각을 기록 (구두라도 시각·방법을 적는다)
- [ ] 우리 맥의 개인키·`~/.ssh/config` 항목 정리

## 5. 미결

- 수신 tailnet 을 회사 명의로 옮길지 담당자 결정 필요(현재 미결).

## 6. kit 스크립트와 이 문서 (전용 계정 전환 뒤)

2026-10-12 결정(아래 "추천 1개"를 그대로 채택)으로 kit의 SSH 단계를 전용 일반 계정 방식으로 바꿨다. 행 번호는 이 판의 것이라 스크립트가 바뀌면 달라진다. **Windows 11 실기 리허설 통과(2026-10-14 체크리스트 17줄, 10/16 재검증 — 비밀번호 SSH 거부·잠김 없음·회수 원복 확인). 고객 PC 첫 적용 때 check.ps1 결과를 개통 기록에 남긴다.**

### 바뀐 뒤 상태
| 항목 | 지금 kit | 이 문서의 절차 |
|---|---|---|
| 순서 | 통로(전용 계정 → OpenSSH → Tailscale)를 먼저 깔고 맥북 확인 뒤 Git·녹화 (`CLAUDE.md` 순서 3~6) | 같음. 문서의 개통 전 체크리스트(1절)가 그 앞에 붙는다 |
| 계정 생성 | 사람이 새 관리자 PowerShell에서 `new-access-account.ps1 -UserName <전용계정>` 실행. Users 그룹만, 암호는 `Read-Host -AsSecureString`. 이미 있으면 만들지 않고 상태만 보고 (`CLAUDE.md` 순서 3) | 같음 |
| 암호 만료 | Windows 기본값(42일) 유지 — 만료 뒤에도 키 로그인 됨(리허설 실측), 화면 로그인 때 새 암호. `new-access-account.ps1`의 `-AccountNeverExpires`는 계정 사용 기한이고 암호 만료와 다르다 | 같음 |
| 접속 계정 | 전용 일반 계정. 공개키는 그 계정의 `.ssh\authorized_keys`, 소유자·ACL = 그 계정·SYSTEM·Administrators (`install.ps1` 185~237행. 프로필 생성·경로 확인은 sshd·방화벽을 바꾸기 전 194~198행). 계정이 없거나 Administrators 소속이면 실패 (88~97행) | 같음. 관리자는 작업 때만 |
| 비밀번호 SSH | 전용 계정만 끈다. 키 등록 뒤 `%ProgramData%\ssh\sshd_config` 끝에 표식 블록(`# BEGIN ax-field-kit access-account <계정>` / `Match User <계정>` / `PasswordAuthentication no` / `# END …`)을 덧붙인다. 넣기 전에 `sshd_config`를 읽어 정적으로 검증한다(`sshd-keyonly.ps1`의 `Test-AccessAccountKeyOnly`): 이 계정의 우리 블록이 정확히 1개, 그 뒤에는 빈 줄·주석 또는 `Match` 줄로 시작하는 블록(다른 전용 계정의 블록·고객 블록)만 와야 함(새 `Match` 줄이 우리 블록을 닫고, 뒤 블록은 처음 얻은 값 규칙 때문에 우리 `no`를 덮지 못함. `Match` 없이 바로 오는 설정 줄은 우리 블록 안으로 들어가므로 실패), 안은 `Match User <계정>`+`PasswordAuthentication no`, 그보다 앞서 이 계정에 적용될 수 있는 Match 블록(`Match All`·`Match User <계정>`·계정이 속한 그룹의 `Match Group`·주소 조건 등, `Match Group administrators`는 해당 없음)에 `PasswordAuthentication`이 없어야 한다(sshd는 처음 얻은 값을 씀). 어긋나면 파일을 바꾸지 않고 멈춤. 같은 블록이 이미 있으면 넣지 않고 같은 검증만 함. 원본 백업 → `sshd -t`(15초 제한) 실패면 원복하고 멈춤 → sshd 재시작 (`install.ps1` 127~164, 233행). `sshd -T -C user=<계정>` 실효값 확인은 쓰지 않는다 — 기본 파일의 `Match Group administrators` 때문에 SYSTEM이 아닌 관리자에서는 `ga_init, unable to resolve user`로 실패하고 PowerShell에서 멈췄다(리허설). **실제 거부 동작은 VM·현장에서 맥에서 비밀번호 SSH를 시도해 거부되는지로 확인한다**(`ssh -o PubkeyAuthentication=no -o PreferredAuthentications=password <계정>@<IP>` → `Permission denied`). 고객의 다른 sshd 설정은 건드리지 않는다 | 같음 |
| 키 표식 | 키 본문만 ASCII로 정규화하고 줄 끝에 `ops-<고객>-<기기>-<날짜>`(영문·숫자·`-`, 아니면 거부) (`install.ps1` 79, 187~191행) | 같음 |
| 계정 회수 | `uninstall.ps1 -SshUser`가 전용 계정 키 → 관리자 키(옛 판 `ax-field-kit` 줄 호환) → 프로필 → 계정 → `sshd_config` 표식 블록 순서로 회수(프로필 삭제가 실패하면 계정을 남김, 표식 블록은 `-SshUser` 계정의 것만 `-KeepSsh`여도 지우고 `sshd -t` 실패면 원복, 다른 전용 계정의 블록은 남김). 계정 삭제는 사람에게 묻고 `new-access-account.ps1`이 만든 계정만 대상 (`uninstall.ps1` 39~86, 113~177행) | 같음 (4절) |
| 점검 | `check.ps1 -SshUser`가 전용 계정 존재·그룹(Administrators면 경고)·잠김·우리 키 줄 수·비밀번호 로그인 꺼짐(install과 같은 정적 검증, 관리자만 — 실제 거부는 위 비밀번호 SSH 시험)을 `Row` 형식(정의 10~13행)으로 출력, 권한 때문에 조회가 막히면 `[확인불가]`로 표시 (60~112행) | 3-1절 잠김 확인과 같음 |

**남은 차이는 Tailscale 가입 방식(우리 키 vs 고객 공유) 하나뿐이다.** 5절 tailnet 명의 결정이 난 뒤에 별도로 정한다.

### 정하지 않고 남긴 것
- `administrators_authorized_keys` 등록은 하지 않는다(호환 스위치도 두지 않음). 그 파일의 키는 이 PC의 **모든 관리자 계정**으로 로그인되기 때문이다. 옛 판이 넣은 `ax-field-kit` 줄 회수만 `uninstall.ps1`이 한다.
- 그래서 전용 계정에 관리자를 임시로 주는 동안에는 sshd가 개인 키 파일을 읽지 않아 키 로그인이 끊긴다(3-2절). 임시 관리자 작업을 원격으로 할지, 현장에서 사람이 할지는 리허설 뒤 정한다.

### 채택한 추천 (기록)
1. 계정 생성은 사람이 직접 — Claude가 도는 흐름에서는 `Read-Host` 입력을 받을 수 없고 암호를 인자·환경 변수·보고서에 남겨서도 안 된다.
2. `install.ps1` SSH 단계는 전용 계정의 `.ssh\authorized_keys`에 기기별 주석 키를 넣는다. 방화벽 규칙은 Tailscale 대역 전용 그대로.
3. `uninstall.ps1`은 일반 계정 키 → 관리자 키 → 계정·프로필 순서로 지운다. `-KeepSsh`는 우리 키만 지우고 서비스·방화벽은 사전 기록대로 사람이 복구.
4. `check.ps1`은 전용 계정 존재·그룹·잠김을 한 줄씩.
5. Tailscale 가입 방식은 tailnet 명의 결정 뒤.

이유: 관리자 상시 소속과 고정 표식 키는 실측 기록에서 "고칠 점"으로 남은 두 가지(상시 관리자·회수 불명확)를 kit이 그대로 반복한다. 계정 단위로 묶으면 회수가 한 번에 끝난다.
