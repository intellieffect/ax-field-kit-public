# 고객 PC 원격 통로 — 개통·회수 절차

1판 2026-10-12. 근거: 한 고객 PC 개통 기록(1시간 20분 걸린 시행착오)과 고객 환경 접속 기준 초안.
비밀값(키·비밀번호·IP·tailnet 이름)은 이 문서와 저장소 어디에도 쓰지 않는다. 사례는 익명으로만 적는다.
개통할 때마다 [양식/원격통로-개통기록.md](양식/원격통로-개통기록.md) 를 복사해 채운다.

## 1. 개통 전 체크리스트

| # | 확인 | 이유 |
|---|---|---|
| 1 | **고객 명의 통로**: 고객이 Tailscale 기기 공유 링크를 열고, 언제든 끊을 수 있게 한다 | 통로의 주인이 고객이어야 회수·중단이 고객 손에 있다 |
| 2 | **로그인·결제·시스템 권한 승인은 고객 손으로** | 우리가 대신 눌러 주지 않는다 |
| 3 | **전용 로컬 계정**을 새로 만든다 (고객 본인 계정 사용 금지) | 아래 2절 |
| 4 | 전용 계정은 **일반 사용자**로 둔다. 관리자 권한은 작업 때만, 고객 승인 후 부여하고 끝나면 회수 | 최소 권한. 부여·회수 시각을 기록 |
| 5 | 개통기록 양식을 복사해 고객·기기·날짜부터 적는다 | 회수 때 무엇을 지울지 기록으로 안다 |

### 왜 고객 본인 계정을 쓰지 않나
- 고객 계정이 **비밀번호 없음**이면 윈도우 기본 정책이 그 계정의 네트워크 로그온을 막는다.
- 풀려면 `LimitBlankPasswordUse` 를 꺼야 하고, 그러면 SMB 파일공유까지 빈 암호로 열린다. **풀지 않는다.**
- 대신 전용 로컬 계정을 만든다. 회수 = 계정 삭제 한 번.

## 2. 키 규칙

| 규칙 | 내용 |
|---|---|
| 기기별 키 | 우리 맥 한 대당 키 하나. 키를 여러 기기에 복사하지 않는다 |
| 주석 | `<운영자약칭>-<고객>-<기기>-<날짜>` (예: `ops-acme-macbook-20261012`). 고객 PC의 공개키 줄에 이 주석이 붙는다. **운영자 약칭과 고객 약칭은 영문·숫자만** 쓴다(한글 금지). 회수 때 `-Encoding ascii`로 파일을 다시 쓰면 비ASCII 글자가 `?`로 바뀌어, 고객의 다른 키 주석까지 망가질 수 있다 |
| 암호 | **모든 개인키에 암호 필수.** 무암호 키 금지. 무인 접속이 꼭 필요하면 별도 판단(담당자 승인) |
| 회수 | 주석으로 우리 키만 골라 지운다(고객의 다른 키는 보존). 3절 회수 체크 참고 |

## 3. 막혔을 때 — 순서

### 3-1. 잠금 정책을 끄지 않는다
`net accounts /lockoutthreshold:0` **금지**. 윈도우 11 은 기본으로 실패 10회에 계정을 잠그는데, 키·비밀번호 설정 중 반복 실패가 계정을 잠가 "한 번 성공한 뒤 다시 막힘"이 생긴다.

1. **먼저 잠김 여부 확인**
   ```powershell
   $u = [ADSI]"WinNT://$env:COMPUTERNAME/<전용계정>,user"
   $u.psbase.InvokeGet('IsAccountLocked')      # True 면 잠김
   ```
   서버 로그에 `0xC0000234`(STATUS_ACCOUNT_LOCKED_OUT)가 보여도 같은 상태다.
2. **해제만 한다**
   ```powershell
   $u.psbase.InvokeSet('IsAccountLocked',$false); $u.psbase.CommitChanges()
   ```
3. 잠긴 근본 원인(반복 실패)을 고친다. 아래 흔한 원인 참고.

### 3-2. 흔한 원인 (먼저 의심할 것)
| 증상 | 원인 | 조치 |
|---|---|---|
| 서버 로그 `Connection closed by authenticating user ... [preauth]` | 서버 거부가 아니라 **클라이언트가 끊은 것**. 개인키에 암호가 걸렸는데 `BatchMode=yes` 라 암호를 물을 수 없어 ssh 가 포기 | 맥에서 `UseKeychain yes`+`AddKeysToAgent yes` 또는 askpass 로 암호 공급. 이 반복 실패가 계정 잠금으로 이어진다 |
| 관리자 계정인데 키가 안 먹음 | 윈도우 sshd 는 Administrators 그룹 계정의 개인 `authorized_keys` 를 읽지 않고 `C:\ProgramData\ssh\administrators_authorized_keys` 만 읽는다 | 해당 파일에 등록 + 소유자 `Administrators` (`icacls <파일> /setowner "Administrators"`) + ACL 정리 + sshd 재시작 |
| `sshd.exe -d` 를 관리자 PowerShell 에서 띄웠더니 항상 `unable to generate user token ... not running as system` | 포그라운드 디버그는 SYSTEM 이 아니라 늘 이 오류로 끝난다 — 진짜 원인이 아님 | 서비스로 돌리고 파일 로깅(`SyslogFacility LOCAL0` / `LogLevel DEBUG3` → `C:\ProgramData\ssh\logs\sshd.log`) |
| `sshd_config` 에 `LogLevel` 을 추가했더니 오류 | 파일 끝에 붙이면 마지막 `Match` 블록 안으로 들어가 허용되지 않는 지시어가 된다 | **첫 `Match` 앞에** 끼워 넣는다 |

### 3-3. 원인이 아니었던 것 (여기서 시간 쓰지 않는다)
한 고객 PC 실측 기록 기준.

| 후보 | 판정 근거 |
|---|---|
| 방화벽 | SSH 인사말 수신 + KEX 완료 — 막는 거라면 거기까지 못 온다 |
| 백신(V3 등) | 위와 동일. 끄지 않고 해결됨 |
| 빈 비밀번호 정책 | 비밀번호를 가진 전용 계정도 똑같이 거부됐다 |
| 네트워크 로그온 거부 정책 | `SeDenyNetworkLogonRight` 에 Guest 만 있었다 |
| sshd 서비스 계정 | `LocalSystem` 확인 |

### 3-4. 고객 보안 설정을 낮춰야 할 때
- 고객 **승인**을 먼저 받는다. 승인 없이 낮추지 않는다(백신·방화벽·실행 정책 끄기 금지는 CLAUDE.md 그대로).
- 무엇을·누가 승인했는지·언제 원복했는지를 개통기록에 적는다. 원복 기록이 없으면 회수가 끝난 것이 아니다.

## 4. 회수 체크 (계약 종료·세션 종료 때)

개통기록 양식의 "회수" 칸을 채우면서 진행한다.

- [ ] 일반 계정 파일부터 정리: 전용 계정의 `.ssh\authorized_keys`에서 우리 키(주석 `<운영자약칭>-<고객>-`)를 지운다. 계정을 지우기 전에 해야 파일 경로가 남아 있다
- [ ] 관리자 권한을 줬었다면 회수하고 시각 기록
- [ ] 관리자 키 파일에서 우리 키만 골라 지운다 (고객의 다른 키는 보존)
  ```powershell
  $A = Join-Path $env:ProgramData "ssh\administrators_authorized_keys"
  (Get-Content $A) | Where-Object { $_ -notmatch '<운영자약칭>-<고객>-' } | Set-Content $A -Encoding ascii
  ```
  `-Encoding ascii`는 비ASCII를 `?`로 바꾼다. 파일에 고객의 한글 주석이 있는지 먼저 보고, 있으면 이 명령을 쓰지 말고 사람이 해당 줄만 직접 지운다.
- [ ] 전용 계정 삭제 (`Remove-LocalUser <전용계정>`) 후 프로필 폴더도 지운다. 계정만 지우면 `C:\Users\<전용계정>`이 남는다
  ```powershell
  Get-CimInstance Win32_UserProfile | Where-Object { $_.LocalPath -like '*\<전용계정>' } | Remove-CimInstance
  ```
- [ ] Tailscale **Sharing 취소** (고객이 공유 링크/기기 공유를 끊음, 또는 관리 콘솔 Machines → ⋯ → Sharing)
- [ ] 낮춘 보안 설정이 있었다면 원복 확인
- [ ] **고객에게 회수 완료를 확인받고** 확인 시각을 기록 (구두라도 시각·방법을 적는다)
- [ ] 우리 맥의 개인키·`~/.ssh/config` 항목 정리

## 5. 미결

- 수신 tailnet 을 회사 명의로 옮길지 결정 필요(현재 미결).

## 6. 이 키트 스크립트와 다른 점 (후속 결정 필요)

이 판의 스크립트(`install.ps1`·`uninstall.ps1`·`check.ps1`)는 이번에 고치지 않았다. 아래는 이 저장소 main(d43f6fd) 기준 `install.ps1`·`uninstall.ps1`·`check.ps1`·`CLAUDE.md`·`README.md`를 읽고 쓴 것이다. 행 번호는 그 판의 것이라 스크립트가 바뀌면 달라진다. 비공개 운영판은 아래 추천(전용 일반 계정 방식)으로 바꾸는 중이며 승인은 받았고 리허설 전이다. 이 공개판은 아직 바뀌지 않았다.

### 차이
| 항목 | 지금 키트 | 이 문서의 절차 |
|---|---|---|
| 순서 | `install.ps1` 은 Git(93~102행) → Claude Code(104~123행) → Tailscale(125~176행) → OpenSSH(178~199행) → 녹화(201~215행). `CLAUDE.md` 는 Claude 가 `-SkipClaude -SkipTailscale` 로 돌린 뒤(순서 3) Tailscale 가입은 사람이 한다(순서 4) | 같음. 문서의 개통 전 체크리스트(1절)가 그 앞에 붙는다 |

| Tailscale | 사람이 새 관리자 PowerShell 에서 우리 인증 키를 입력해 우리 테일넷에 가입한다(`-TsTag` 로 태그, 141~175행, `CLAUDE.md` 순서 4). 가입할 테일넷이 맞는지 확인하는 단계는 없다. 철수는 `tailscale logout` (`uninstall.ps1` 52~55행) | 고객 명의, 고객이 기기 공유 |
| 개통 기록 | `check.ps1` 은 상태 점검만 (10~42행). 보고서는 `CLAUDE.md` 순서 8의 `setup-report.md` | 개통기록 양식 |
| 계정 잠금 | 확인하지 않는다 | `IsAccountLocked` 확인 (3-1절) |

### 추천 1개 — SSH 단계를 "전용 일반 계정" 방식으로 바꾸고, 계정 생성은 사람이 한다
1. **계정 생성은 사람이 직접.** 전용 로컬 계정을 일반 사용자(Users 그룹)로 만들고 암호를 정하는 일은 Tailscale 인증 키 입력(`CLAUDE.md` 순서 4)처럼 사람이 새 관리자 PowerShell 에서 한다. Claude 가 `install.ps1` 을 돌리는 흐름에서는 `Read-Host` 입력을 받을 수 없고, 암호를 인자·환경 변수·보고서에 남겨서도 안 된다. 스크립트가 계정을 만들게 하려면 사람이 실행하는 별도 스크립트로 분리하고, 임시 파일은 `install.ps1` 155~171행과 같이 ACL 을 먼저 적용한 뒤 `finally` 에서 지운다.
2. **`install.ps1`**: SSH 단계(179~199행)에 전용 계정 이름 매개변수를 추가해, 공개키를 `administrators_authorized_keys` 가 아니라 **그 계정의 `.ssh\authorized_keys`**(소유자·ACL 정리 포함)에 넣는다. 키 줄 끝 표식은 `ax-field-kit` 대신 주석 `<운영자약칭>-<고객>-<기기>-<날짜>`(영문·숫자)로 받는다. 방화벽 규칙은 지금처럼 Tailscale 대역 전용으로 둔다(185~189행).
3. **`uninstall.ps1`**: OpenSSH 정리 단계(36~50행)에서 일반 계정 키 → 관리자 키 → 계정·프로필 삭제 순서(4절)로 지운다. 기존 `ax-field-kit` 표식 줄 제거는 호환을 위해 남긴다. 지금 `-KeepSsh` 는 sshd 와 공개키를 모두 그대로 두므로(37행), 우리 키만 지우고 서비스·방화벽 상태는 원래대로 두는 옵션이 따로 필요하다.
4. **`check.ps1`**: 전용 계정 존재·그룹 소속(Administrators 상시 소속이면 경고)·`IsAccountLocked` 상태를 한 줄씩 출력한다(기존 `Row` 형식, 5~8행).
5. Tailscale 가입 방식(우리 키 vs 고객 공유)은 5절 tailnet 명의 결정이 난 뒤에 별도로 정한다.

이유: 관리자 상시 소속과 고정 표식 키는 실측 기록에서 "고칠 점"으로 남은 두 가지(상시 관리자·회수 불명확)를 키트가 그대로 반복한다. 계정 단위로 묶으면 회수가 한 번에 끝난다.
